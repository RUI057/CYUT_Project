# 台灣手語即時辨識系統

手語詞彙識別與自然語言轉換系統，使用深度學習進行即時的手語動作識別。

## 概述

本項目結合 MediaPipe 手部關鍵點檢測、PyTorch LSTM 時間序列模型及本機語言模型（可切換 Gemini API），建構一套從手語捕捉、特徵提取、詞彙識別到自然語言轉換的完整流程。系統支持本地訓練與推理，同時提供文字轉語音功能。

## 核心功能

- 攝影機實時手語捕捉與特徵提取
- 基於 LSTM 的時間序列詞彙識別
- 本機語言模型語義修正與自然句子生成（離線、免 API 金鑰；可切換 Gemini）
- Google TTS 文字語音合成
- 訓練資料的自動收集與管理

## 工作流程

### 數據收集

```bash
python collect_data.py
```

選定詞彙後，手部穩定出現即自動連續錄製每筆 30 幀序列。按鍵控制：
- N / M: 下一個 / 上一個詞彙
- D: 刪除上一筆
- S: 暫停 / 繼續偵測（切換詞彙時會自動暫停，避免誤觸）
- Q: 離開

### 合併組員的資料

```bash
python merge_data.py 手語資料_小明_20260920.zip        # 收集包「打包資料」產生的 zip
python merge_data.py ~/Downloads/dynamic_dataset       # 組員直接給的資料夾也可以
python merge_data.py 資料夾/ 某人.zip                   # 混著給、一次多個都行
python merge_data.py <來源> --dry-run                   # 只列出會加什麼，不寫入
```

- **同名檔案一律跳過、絕不覆蓋**，所以同一份來源合併兩次也不會出事
- 詞不在詞彙表、檔案讀不了或形狀不對 → 跳過並列出
- 來源與目的地互相包含時會擋下來（避免自己合併自己）

> ⚠️ 不要用 Finder／檔案總管直接把資料夾拖過去：跳出「取代」時按下去，
> 會把整個詞資料夾換掉，原本的資料就沒了。

合併完建議先跑 `python check_dataset.py` 檢查品質，再訓練。

### 模型訓練

```bash
python train_model.py
```

使用 dynamic_dataset 中的訓練數據訓練 LSTM 模型。訓練參數：
- 序列長度: 30 幀
- 特徵維度: 162（雙手 126 + 臉部 36；啟用位置時 168，見「特徵提取」）
- 隱藏層: 128 單位，2 層雙向
- 批次: 32
- 訓練周期: 60
- 學習率: 1e-3

訓練時自動套用尺度正規化、資料增強（時間伸縮 / 旋轉 / 抖動）與類別權重（緩解樣本不平衡）。
訓練結束會印出 classification report 與「最常誤判的詞對」，並生成 data/model.pkl；
交叉驗證的結果另存到 data/model_report.txt，規劃要補收或重收哪些詞時可以對照。

### 實時測試

```bash
python test_model.py
```

啟動攝影機進行即時識別（OpenCV 視窗）。

### 網頁即時翻譯

```bash
python web.py                      # 預設 http://127.0.0.1:8000
python web.py --port 9000 --host 0.0.0.0   # 讓同網段的手機/平板也能看
```

1. 按「啟動攝影機」，對著鏡頭比手語，系統即時辨識並累積詞彙
2. 手離開畫面（停頓）→ 自動將詞彙序列交給本機語言模型轉成自然中文句子（句子下方會標示由哪個後端產生）
3. gTTS 朗讀句子，並保存到翻譯紀錄
4. 也可手動按「翻譯 / 朗讀 / 清除」，右側可調信心門檻、確認幀數與自動翻譯停頓

**為什麼用 FastAPI + MJPEG**：Streamlit 的執行模型是「整頁重跑」，推即時影像得靠一個不會結束的
迴圈撐著，按鈕和設定都要跟這個迴圈搶執行權。`web.py` 把職責切開：

- 擷取執行緒獨佔攝影機與 MediaPipe（兩者都不是執行緒安全的），負責辨識與 JPEG 編碼
- `/stream` 以 `multipart/x-mixed-replace` 把**同一份** JPEG 丟給所有連線，不是每個連線各編一次
- 翻譯／TTS 另開執行緒：本機語言模型很慢，不能卡住影像串流或事件迴圈
- 其他端點（`/state`、`/translate`、`/clear`、`/settings`）隨時可用，不受影像迴圈影響

> macOS 注意：攝影機授權請求只能在主執行緒發出，`web.py` 啟動時會先在主執行緒開一次攝影機
> 觸發授權視窗。若第一次使用沒跳出視窗又開不起來，到「系統設定 → 隱私權與安全性 → 攝影機」
> 手動允許終端機。

舊版 Streamlit 介面仍可用：`streamlit run app.py`。

## 技術細節

### 特徵提取

使用 MediaPipe 檢測雙手各 21 個關鍵點的 (x, y, z) 座標，相對手腕做平移正規化（左手 63 維 + 右手 63 維 = 126 維）。餵入模型前再對每隻手做尺度正規化（除以手部大小），消除離鏡頭遠近造成的誤判。特徵抽取與正規化集中於 `src/features.py`，收集 / 訓練 / 推理三端共用以確保一致。

每筆資料存成 170 維：雙手 126 + 臉部表情 36 + 位置 8。手部相對手腕、臉部相對鼻尖，兩者都看不到「手在哪裡」，所以另存手腕與鼻尖的畫面座標和臉的寬高，正規化時換算成「手腕相對鼻尖、以臉寬 / 臉高為單位」的位置（加上鼻尖的移動 = 點頭、搖頭）。用臉當基準點，站遠站近、站在畫面哪裡、鏡頭是 16:9 還是 4:3 都不影響；臉短暫被手擋住時用前後幀的鼻尖補回。臉部表情與位置特徵預設停用（`use_face` / `use_loc` 旗標），因為舊資料沒有，只有部分詞有時模型會靠「有沒有資料」作弊；每個詞都收夠之後以 `train_model.py --face` / `--loc` 啟用。停用時模型輸入仍為 162 維，與舊模型相容。

### 模型架構

雙向 LSTM 用于捕捉時間序列中的手語動作特征：
- 輸入: (batch_size, 30, 126)
- 雙向 LSTM: 128 隱藏單位，2 層（輸出 256 維 / 幀）
- 特徵融合: 時間維度平均池化 + 最大池化（256 × 2 = 512 維）
- 全連接層: 512 -> 64 (ReLU) -> num_classes

### 語義修正（src/translate.py）

手語辨識出的是手語語序的詞彙序列（例如「明天、我、學校、去」），由本機語言模型改寫成自然中文（「我明天要去學校。」）：

- **模型**：Qwen2.5-1.5B-Instruct。與 Qwen3-1.7B、Qwen3.5-0.8B、Qwen3.5-2B 比較後選定——語意錯誤最少、速度最快（Apple M5 平均 0.4 秒 / 句），且是標準注意力架構，Windows 純 CPU 也跑得動；Qwen3.5 系列會把「我 你 愛」翻成「你愛我」，且在沒有專用 kernel 的電腦上很慢
- **Prompt**：系統指示 + 7 組少樣本範例（示範時間詞在前、疑問詞在句尾的手語語序），解碼不隨機，結果可重現
- **單一個詞不問模型**：真實使用約 6 成是單詞（誰、你好、名字），模型在這裡只會亂補（「怎麼辦」→「怎麼辦了？」），所以直接用規則輸出：疑問詞加「？」、招呼語加「！」、其餘加「。」
- **束搜尋＋忠實度排序**：模型一次產生 6 個候選（`POLISH_BEAMS` 調整，1 = 關閉），不是只取第一名。排序是分層的：先擋掉硬問題（漏詞、自己加疑問詞、混進英文），再擋自己多加的動詞（「我 讀書」→「我要讀書」、「我 不會 手語」→「我不會說手語」），同層才比「模型信心 − 多加字數 − 詞序被打亂」。每句約 1.5～2 秒（Apple M5）
- **自我修正**：選出的句子仍有漏詞、多加疑問詞或混進英文時，把問題回饋給模型重寫一次；真的變好才採用
- **後處理**：OpenCC 轉台灣繁體（小模型偶爾冒出簡體字）；輸出太長或幾乎沒用到原詞時視為離題並擋下
- **退路**：本機模型失敗 → Gemini（有金鑰時）→ 直接以「、」串接詞彙，網頁不會因翻譯而中斷

**準確度怎麼量**：`python eval_semantic.py`（`--show-fail` 看錯在哪、`--beams 1` 對照貪婪解碼）。
評測集是 100 多句「詞彙序列 → 可接受的說法」，分調參集／保留集／盲測集，改翻譯邏輯時請照檔頭的紀律
（盲寫新句子、改完只跑一次），否則很容易被自己騙到。2026-10-25 結果（Qwen2.5-1.5B）：

| 評測集 | 舊流程（貪婪解碼） | 現行 |
|---|---|---|
| 調參集 | 78% | 97% |
| 保留集 | 69% | 86% |
| 驗證集（改之前盲寫） | 56% | 84% |
| 盲測集（定案後只跑一次） | 71% | **92%** |

已知限制：輸入不完整時（「你好 我 名字」）仍會被補成問句；沒有疑問詞的句子（「你 會 手語」）模型傾向猜成疑問句；
沒有臉部表情資訊，無法分辨陳述與是非問句。

### 詞彙管理

vocabulary.json 定義所有可識別的詞彙，修改后需重新收集數據並訓練模型。

## 詞彙列表

詞彙表共 114 個詞（`data/vocabulary.json`），著重日常使用、問問題、數字與學校（朝陽科大校園），截至 2026-10 其中 71 個已有資料。
「問路」「問問題」這類片語不另設一個詞，而是分別辨識「問＋路」「問＋問題」，再由語義修正組回完整句子（一筆錄製只有 30 幀，約 1 秒，比不完兩個手勢）。
收集進度可用 `python start.py` →「查看進度」查看。

## 性能參考

2026-09，90 個詞、8,313 筆資料：
- 5-fold 交叉驗證準確率 71.1%（session-aware 切分：同一次錄製的樣本不會同時出現在訓練與驗證，
  數字比「隨機切分」誠實，也因此比早期 25 詞時的數字低，兩者不可直接比較）
- 本機語義修正：單詞即時（規則）；多詞句 Apple M 系列約 1.5～2 秒 / 句（束搜尋 6 個候選，`POLISH_BEAMS=1` 可回到約 0.4 秒但準確度較低）
